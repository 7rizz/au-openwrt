# 校园网防检测（UA3F / UA2F）+ 自动登录 · 使用说明

这个固件版本把你放在电脑里的那一整套东西**全部内置**了，刷完即用，不用再往路由器上传 ipk。

> 合规提醒：绕过校园网共享限制通常违反学校网络管理规定，可能导致断网、封号甚至纪律处理。
> 请自行判断并承担后果。先看到本文最后一节"怎么回滚"再动手。

---

## 一、固件里内置了什么

| 组件 | 位置 / 界面 | 作用 |
| --- | --- | --- |
| **UA3F 3.7.0**（主引擎，默认开） | 菜单「服务 → UA3F」 | 改 UA + 固定 TTL + 清 TCP 时间戳 + IPID 归零，一条链路解决最常见的三种检测 |
| **UA2F 4.10.2**（备引擎，默认关） | 无独立菜单，命令行 `ua-engine ua2f` 切换 | 内核态改 UA，更省资源，只做 UA 这一件事 |
| **引擎开关 `ua-engine`** | 路由器 SSH | `ua-engine ua3f` / `ua2f` / `off` / `status`，保证两个引擎不同时跑 |
| **顺枫公寓自动登录 netcheck**（你自己写的） | 菜单「服务 → 顺枫公寓自动登录」 | 断线自动重登，账号要在 `/etc/auth.conf` 里填，带日志和一键测试 |
| 另外两个自建页面 | 菜单「服务」下 | 连接设备、WAN MAC 工具 |
| 运维脚本 | 路由器上 `/root/` | `firewall-antidetect.sh`、`verify.sh` |
| 部署文档 | 路由器上 `/root/ua-docs/` | 01~07 全套文档 |

**开箱状态**：引擎 = UA3F（`enabled 1`），模式 = TPROXY，监听 `0.0.0.0:1080`，人格 = **Windows（TTL 128）**，
清 TCP 时间戳、IPID 归零已开；阻断 QUIC / Desync / MitM 已关（MT7621 上开了容易掉线）。
自动登录默认**不会**自己跑：`/etc/auth.conf` 里的学号密码故意留空，填上并 `uci set` 之后 `99-personal` 才会启用它。

## 二、刷完先做三件事

1. 连上 WiFi（2.4G `破解校园网V：aauuo0` / 5G `破解校园网联系v：aauuo0`，密码 `aaaauuuu`），进后台 `http://192.168.1.1`（密码 `root`）。
2. 打开「服务 → 顺枫公寓自动登录」，看最下面的日志：出现 `SUCCESS` 就说明已经在替你自动登录了。
3. 打开「服务 → UA3F」，确认「启用」是勾上的、进程在跑（或者 SSH 里 `ua-engine status`，应显示 UA3F 在跑、UA2F 没跑）。

## 三、人格怎么选（这一步决定了会不会被检测）

检测的核心逻辑是"同一账号下是否出现了互相矛盾的系统特征"，所以规则是：

**选你平时认证/绑定校园网账号时用的那台设备的人格。**

| 你认证时用的设备 | 人格选 | TTL |
| --- | --- | --- |
| 手机（iPhone） | iPhone | 64 |
| 手机（安卓） | Android | 64 |
| 电脑（Windows） | Windows（**默认**） | 128 |

**最省事的换法**：菜单「服务 → 防检测引擎」→ 顶部「认证人格」点一下就行。
它会 **UA + TTL 成套换**，并且把 UA3F（连规则里写死的改写值）和 UA2F 一起同步，
正在跑的那个引擎自动重启，另一个不动。

比如默认是电脑 128，临时要用手机账号认证，就点「手机 iPhone · TTL 64」，切回电脑再点回来——
不用记 UA 串，也不会出现"UA 是手机、TTL 还是 128"这种自相矛盾。

下面是要手动改的话怎么改：

**① 页面**：「服务 → UA3F 防检测」里改 `ua`（UA 串）和 `l3_rewrite_ttl_value`（**默认 128＝电脑**，64＝手机），保存并应用。

**② 命令行**（一次改完，注意 UA 和 TTL 要配套）：

```sh
# 默认就是 Windows 人格（TTL 128）：
uci set ua3f.main.ua='Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36'
uci set ua3f.main.l3_rewrite_ttl_value='128'

# 想换成 iPhone 人格（TTL 64）就把上面两行换成：
# uci set ua3f.main.ua='Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1'
# uci set ua3f.main.l3_rewrite_ttl_value='64'

uci commit ua3f && /etc/init.d/ua3f restart
```

> 只改了 UA 没改 TTL（或者反过来）等于自相矛盾，比不改还容易被抓，注意配套

## 四、怎么确认真的生效了

1. **看 UA**：在内网设备上（**关掉系统代理和 VPN**）打开 <http://ua-check.stagoh.com>，
   也可以直接开路由器上的 <http://192.168.1.1/ua-check.html>（走 httpbin），
   显示的是你设置的那条 iPhone/Windows UA（不是设备真实 UA）就说明改写生效了。
2. **看 TTL**：路由器上执行
   ```sh
   tcpdump -i br-lan -vv -c 20 'tcp and port 80'
   ```
   出包的 `ttl` 应该稳定是你设的值（64 或 128），**不该出现 63**。
3. **一键自检**：路由器上执行
   ```sh
   sh /root/verify.sh
   ```
4. **最终验证是实际使用**：多台设备同时上网、看视频、刷手机，看还会不会被断。

## 五、常见问题

**Q：UA3F 起来了但上不了网？**
先在「服务 → UA3F」里把 `server_mode` 从 `TPROXY` 换成 `REDIRECT` 试一次（保存并应用），
两种模式在不同学校网关下表现不同；再不行 `ua-engine off` 确认是不是它导致断网。

**Q：微信 / B 站 / Steam 登录异常？**
UA3F 默认用 RULE 模式，已经对 `MicroMessenger`、`Bilibili`、`Steam` 客户端放行（直接不改），
一般不会出问题。真遇到别的 App 异常，在 UA3F 页面的 header 规则里把它设成 DIRECT。

**Q：还要不要跑 `firewall-antidetect.sh`？**
不用。UA3F 的 L3 重写（`l3_rewrite_ttl` / `tcpts` / `ipid`）已经把 TTL、TCP 时间戳、IPID 接管了，
而且是随服务启动、**开机自动重建**（脚本手工执行的那些规则重启就没了，这是个常见坑）。那个脚本留给你手动折腾时用。

**Q：学校是 802.1X 认证（不是网页认证）怎么办？**
这个固件里的 netcheck 是**网页认证（门户 webauth.do）**用的，802.1X 用不了它。
那种情况需要另外装 `minieap` / `mentohust` 这类客户端，告诉我你学校用的是哪种，我给你加进去。

**Q：日志在哪？**
```sh
tail -f /tmp/netcheck.log        # 自动登录
logread | grep -i ua3f           # UA3F
```

## 六、网速变慢了怎么查（UA3F 的老毛病）

UA3F 是**用户态代理**：流量要先从内核搬到它的进程里、改完再搬回去。AC2100 的 MT7621 是双核 880MHz 的 MIPS32，
在这台机器上"能跑"和"跑得快"是两回事。慢通常来自下面几处，按影响从大到小：

| 原因 | 怎么判断 | 怎么解 |
| --- | --- | --- |
| **L3 重写里的 IPID / TCP 时间戳**（最费） | `ua-engine status` 里看到 `TCPts=1` 或 `IPID=1` | `ua-engine fast` 复位（只留 TTL） |
| **TPROXY 把全部 TCP 都接管了，包括 443** | 开网页、看视频都慢，`top` 里 `ua3f` 占满一个核 | 接受它，或者改用 UA2F（见下） |
| 内存吃紧（128MB，Go 的 GC） | `free` 剩得很少、`dmesg` 里有 oom | 关掉 OpenClash / AdGuard 这类大件 |

**档位只有「速度档」**（只固定 TTL，nft 内核态，几乎零开销）。
均衡档（TTL+IPID）和隐蔽档（TTL+IPID+TCPts）在这台机器上已下线 —— 它们都要逐包走 NFQUEUE，
而 eBPF 加速不支持 MIPS32（上游实测 NFQUEUE 44.9% CPU / eBPF 7.9%），开了就是拿网速换那一点点隐蔽度，
不划算。防检测靠 **TTL + UA 统一**这两件事已经足够遮住最常见的检查。

一句话：**均衡档只多花"改 2 字节"的钱，却把 NAT 下设备数这个最常被查的信号遮住了**，性价比最高。

**为什么 IPID / TCP 时间戳这么贵**：这两项要改包头内容，UA3F 只能把包经 NFQUEUE 送到用户态、改完再送回，
一来一回两次拷贝。上游文档写得很明确：没开 eBPF 时走的就是这条路径，
NFQUEUE 实测 CPU 44.9%、eBPF 7.9%；而 **eBPF 加速不支持 MIPS32** —— AC2100 永远用不上。
所以在这台机器上，这两项就是"拿一大截网速换隐蔽度"。

**TTL 不贵**：它是 nft 规则在核心里直接改的，不进用户态，所以速度档照样保留固定 TTL。

**和 mwan3 的冲突**：`full` 版会装上 mwan3（多拨/多线），它和 UA 引擎抢同一套 `fwmark` / `ip rule`，
两个都开的话 TPROXY 会直接失效（表现为"代理没生效、UA 没改"）。
固件的首次开机脚本已经把 mwan3 停掉并取消自启；如果你确实要用多拨，先 `ua-engine off` 再开 mwan3。
同理：OpenClash / PassWall / SSR-Plus 这些透明代理也别和 UA 引擎同时开（它们默认都不自启）。

**实测对比**（刷完固件，SSH 里执行，同一个测速源、同一时间）：

```sh
ua-engine status ; sleep 3 ; top -d1 -n2 | grep ua3f   # 看档位 + CPU
ua-engine fast   ; sleep 3 ; top -d1 -n2 | grep ua3f   # 复位后再看一次
```

**如果还是不够快**：那就是 TPROXY 本身的成本，只能换引擎——

```sh
ua-engine ua2f     # 只接管 HTTP(80)，HTTPS 完全不经过它，速度基本恢复
```

代价是 UA2F 只改 UA，不做 IPID / TCP 时间戳（TTL 由它自带的 `ua2f-ttl` 补）。
一句话：**要速度选 UA2F，要防检测选 UA3F（速度档：TTL + UA 统一）。**

## 七、怎么回滚 / 关掉

不想用了（或者被学校找上门 😅）：

```sh
# 只关防检测、保留自动登录（两个引擎一起停，并改成"开机不自启"）
ua-engine off

# 只想临时停 UA3F（重启后还会自启）
/etc/init.d/ua3f stop

# 彻底关闭自动登录
/etc/init.d/netcheck stop ; /etc/init.d/netcheck disable

# 想换回 UA2F（同一个账号、同一套伪装特征）
ua-engine ua2f
```

`ua-engine off` 会停掉进程、并让开机不再自启。UA3F 3.7.0 的 TPROXY/iptables 规则是程序自己装的，
正常退出会撤掉；万一手工 `kill -9` 过、发现规则残留，重启一次路由器就干净了。

改动前建议先留个备份：`uci export > /root/uci.bak`。

## 七、偶发断线怎么查（"突然断几秒又自己好了"）

这台机器上会造成这种"闪断"的就那么几种，按可能性排：

| 现象 | 原因 | 怎么确认 | 怎么处理 |
| --- | --- | --- | --- |
| **所有设备**同时断 3~10 秒，之后自己恢复 | `ua3f` 进程崩了，procd 隔几秒把它重新拉起来；它一重启，经过它的所有连接都会断 | `logread \| grep -i ua3f`；`/root/flap-watch.sh` 里 ua3f 的 pid 变了 | 128MB 跑 Go 容易 OOM。关掉不用的大插件；`dmesg \| grep -i oom` 确认 |
| 新连接一片失败，几秒后恢复 | conntrack 表满（默认 16384，TPROXY 下很容易打满） | `cat /proc/sys/net/netfilter/nf_conntrack_count` 接近上限 | 固件已抬到 32768；还满就查谁在刷连接（P2P/迅雷/网盘） |
| 只有某台设备掉 Wi-Fi，图标也会重连 | 无线侧 | `logread \| grep hostapd` 里有 deauth/disassoc | 5G 已经是 149（非 DFS），没问题；再不行把 VHT80 降成 VHT40 |
| Wi-Fi 连着但上不了网 | 上游掉线 / 重新认证 | `ping 192.168.1.1` 通、`ping 223.5.5.5` 不通 | 自动登录在重连，等 10~30 秒；持续掉就看 `/tmp/netcheck.log` |

**一键抓现场**（只读，不改任何配置）：

```sh
sh /root/flap-watch.sh 30      # 采样 30 分钟，每秒记一次状态变化
tail -n 80 /tmp/flap.log       # 断一次之后，把这 80 行截出来
```

日志里 `STATE ua3f=1234` 这行的 pid 如果变了，就是引擎重启过；
`conntrack=` 接近 32768 就是表满。

日志环形缓冲已经从 16KB 调到 256KB（`system.@system[0].log_size=256`），
默认那点空间几秒钟就被刷掉，根本留不住证据。
