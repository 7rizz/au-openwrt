# 校园网防检测（UA3F / UA2F）+ 自动登录 · 使用说明

这个固件版本把你放在电脑里的那一整套东西**全部内置**了，刷完即用，不用再往路由器上传 ipk。

> 合规提醒：绕过校园网共享限制通常违反学校网络管理规定，可能导致断网、封号甚至纪律处理。
> 请自行判断并承担后果。先看到本文最后一节"怎么回滚"再动手。

---

## 一、固件里内置了什么

| 组件 | 位置 / 界面 | 作用 |
| --- | --- | --- |
| **UA3F 3.7.0**（主引擎） | 菜单「服务 → UA3F」 | 改 UA + 固定 TTL + 清 TCP 时间戳 + IPID 归零，一条链路解决最常见的三种检测 |
| **UA2F 4.10.2**（备引擎） | 无独立菜单，由防检测中心切换 | 内核态改 UA，更省资源，只做 UA 这一件事 |
| **UA 防检测中心**（你自己写的） | 菜单「服务 → UA 防检测中心」 | 两个引擎一键切换、人格（iPhone/Android/Windows）、各开关、TTL |
| **顺枫公寓自动登录 netcheck**（你自己写的） | 菜单「服务 → 顺枫公寓自动登录」 | 断线自动重登，账号已预填，带日志和一键测试 |
| 三个运维脚本 | 路由器上 `/root/` | `ac2100-setup.sh`、`firewall-antidetect.sh`、`verify.sh` |
| 部署文档 | 路由器上 `/root/ua3f-docs/` | 你写的 01~07 全套文档 |

**开箱状态**：引擎 = UA3F，模式 = TPROXY，人格 = iPhone（TTL 64），
清 TCP 时间戳、IPID 归零已开；阻断 QUIC / Desync / MitM 已关（MT7621 上开了容易掉线）。
auto-login 用的账号密码就是 `/etc/auth.conf` 里你原来的那份。

## 二、刷完先做三件事

1. 连上 WiFi（2.4G `破解校园网V：aauuo0` / 5G `破解校园网联系v：aauuo0`，密码 `aaaauuuu`），进后台 `http://192.168.1.1`（密码 `root`）。
2. 打开「服务 → 顺枫公寓自动登录」，看最下面的日志：出现 `SUCCESS` 就说明已经在替你自动登录了。
3. 打开「服务 → UA 防检测中心」，确认显示 **当前引擎：UA3F**、**运行中**。没运行就点一下「保存并应用」。

## 三、人格怎么选（这一步决定了会不会被检测）

检测的核心逻辑是"同一账号下是否出现了互相矛盾的系统特征"，所以规则是：

**选你平时认证/绑定校园网账号时用的那台设备的人格。**

| 你认证时用的设备 | 人格选 | TTL |
| --- | --- | --- |
| 手机（iPhone） | iPhone | 64 |
| 手机（安卓） | Android | 64 |
| 电脑（Windows） | Windows | 128 |

在「UA 防检测中心」里点对应的人格即可（会自动配套 UA 和 TTL）。
命令行等价操作：

```sh
ua-detect-ctl set persona iphone     # 或 android / windows
```

## 四、怎么确认真的生效了

1. **看 UA**：在内网设备上（**关掉系统代理和 VPN**）打开 <http://ua-check.stagoh.com> 或 <http://ua.233996.xyz>，
   （防检测中心面板里也放了这两个按钮，直接点就行），
   如果显示的就是你设置的那个 UA，说明改写生效了。
2. **看 TTL**：路由器上执行
   ```sh
   tcpdump -i br-lan -vv -c 20 'tcp and port 80'
   ```
   出包的 `ttl` 应该稳定是你设的值（64 或 128），**不该出现 63**。
3. **一键自检**：路由器上执行
   ```sh
   sh /root/verify.sh
   ```
4. **最终验证是实际使用**：多台设备同时上网、看视频、刷手机，看还会不会被断。

## 五、常见问题

**Q：UA3F 起来了但上不了网？**
把服务模式从 TPROXY 换成 REDIRECT 再试（防检测中心里改，或 `ua-detect-ctl set engine ua3f`
后在 UA3F 页面改）。两种模式在不同学校网关下表现不同。

**Q：微信 / B 站 / Steam 登录异常？**
UA3F 默认用 RULE 模式，已经对 `MicroMessenger`、`Bilibili`、`Steam` 客户端放行（直接不改），
一般不会出问题。真遇到别的 App 异常，在 UA3F 页面把它加进 header 规则里设为 DIRECT。

**Q：还要不要跑 `firewall-antidetect.sh`？**
不用。防检测中心里的"固定 TTL / 自动配置防火墙"已经把这些 nft 规则接管了，而且会**开机自动重建**
（脚本手工执行的规则重启就没了，这是个常见坑）。那个脚本留给你手动折腾时用。

**Q：学校是 802.1X 认证（不是网页认证）怎么办？**
这个固件里的 netcheck 是**网页认证（门户 webauth.do）**用的，802.1X 用不了它。
那种情况需要另外装 `minieap` / `mentohust` 这类客户端，告诉我你学校用的是哪种，我给你加进去。

**Q：日志在哪？**
```sh
tail -f /tmp/netcheck.log        # 自动登录
logread | grep -i ua3f           # UA3F
```

## 六、怎么回滚 / 关掉

不想用了（或者被学校找上门 😅）：

```sh
# 只关防检测，保留自动登录
ua-detect-ctl set enabled 0

# 临时停掉 UA3F
/etc/init.d/ua3f stop ; /etc/init.d/ua3f disable

# 彻底关闭自动登录
/etc/init.d/netcheck stop ; /etc/init.d/netcheck disable

# 移除内核里的 TTL/NTP 规则
ua-detect-ctl firewall-off
```

改动前建议先留个备份：`uci export > /root/uci.bak`。
