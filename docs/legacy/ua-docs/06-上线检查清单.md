# 06 · 上线检查清单

部署完，照这张表勾一遍再投入使用。

## 部署前

- [ ] 已确认路由器型号、OpenWrt 版本、CPU 架构。
- [ ] 已确认包管理器是 `opkg`（下 ipk）还是 `apk`（下 apk）。
- [ ] 已备份当前配置（至少 `uci export firewall > /root/firewall.bak`）。
- [ ] 已知晓本校对共享上网的规定与可能的处罚，自行决定是否继续。

## 部署中

- [ ] 已安装 nftables 队列依赖（UA2F 透明模式）：`kmod-nft-queue`、`kmod-nft-tproxy`。
- [ ] 已安装 UA2F 或 UA2F 对应架构的包。
- [ ] 已选定"人格"（iPhone=64 / Windows=128），UA 与 TTL 匹配同一人格。
- [ ] 重写模式：GLOBAL（全改）或 RULE（按规则，微信/Steam/B 站等放行）。
- [ ] 只开了确认需要的功能，QUIC 阻断 / Desync / MitM **默认不开**。
- [ ] 若与 Clash 共存：`PROCESS-NAME,ua2f,DIRECT` 在规则最顶端。
- [ ] Fake-IP 场景下 OpenClash DNS 劫持选了"使用防火墙转发"。

## 验证

- [ ] 测试站（<http://ua-check.stagoh.com>）显示 UA 已被统一。
- [ ] 抓包确认 TTL 稳定为设定值（不是 63/127）。
- [ ] 内网每台设备都能正常上网、看视频、收发微信。
- [ ] 连续使用一段时间（几小时）没有被断网 / 封号。
- [ ] 关掉 VPN / 代理后，UA 修改依然生效（说明是路由器侧在起作用）。

## 长期

- [ ] 记录当前可用配置（`uci export ua2f`、`cat /etc/config/ua2f`）到本地，方便翻车后恢复。
- [ ] 关注 UA2F 更新（老版本遇到新 OpenWrt 可能会有兼容问题）。
- [ ] 不要对同一账号做高调的异常流量（高频扫描、跑 P2P 等），那会以别的方式引起注意。
