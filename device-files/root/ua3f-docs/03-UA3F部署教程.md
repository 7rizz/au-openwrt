# 03 · UA3F 部署教程（主推方案）

本文按"从零到能上网且检测通过"的顺序写。每一步都给出可复制的命令或 LuCI 操作路径。

> 参考资料：[UA3F 官方文档](https://ua3f.sunbk201.site/zh/)、
> [猴子也能看懂的 UA3F 使用教程](https://sunbk201public.notion.site/UA3F-2a21f32cbb4b80669e04ec1f053d0333)。

---

## 0. 前置条件

- 一台已刷 **OpenWrt** 的路由器，能正常上网、能做网关。
- 路由器能 SSH（LuCI 里"系统 → 管理权"设置密码后即可）。
- 内存建议 ≥ 128MB（UA3F 是用户态程序，比纯内核模块吃资源，但一般够用）。

UA3F 支持 5 种服务模式，校园网场景最常用两种：

| 模式 | 是否需要 Clash | 说明 |
| --- | --- | --- |
| **TPROXY** | 否 | 网关透明接管，**推荐**，性能好 |
| **REDIRECT** | 否 | 备选，TPROXY 出问题时换它 |
| SOCKS5 / HTTP | 是 | 由 Clash 把流量转给 UA3F，适合还想用加密代理的场景 |
| NFQUEUE | 否 | 兼容性最差，一般不用 |

下面分两条路线：**A. 不依赖 Clash（推荐先试）** 和 **B. 与 Clash 共存**。

---

## 1. 确认版本、架构、包管理器

SSH 进路由器后执行：

```sh
# 看包管理器是 opkg 还是 apk（决定下 .ipk 还是 .apk）
which opkg
which apk

# 看 OpenWrt 版本
. /etc/openwrt_release && echo $DISTRIB_RELEASE

# 看 CPU 架构（决定下哪个架构的包）
opkg print-architecture 2>/dev/null || apk info --print-arch
```

对应关系（来自 UA3F 官方说明）：

- **OpenWrt 24.10 及更老版本 → `opkg` → 下 `.ipk`**
- **OpenWrt 25.12 及更新版本 → `apk` → 下 `.apk`**
- 架构取 `opkg print-architecture` 里**优先级数字最大**那一行里的关键字，例如输出：
  ```
  arch all 1
  arch noarch 1
  arch aarch64_cortex-a53 10
  ```
  那就该选 `aarch64_cortex-a53`。

到 [UA3F Releases](https://github.com/SunBK201/UA3F/releases) 下载对应文件，例如
`ua3f-3.7.0-r1-aarch64_cortex-a53.apk` 或 `ua3f_3.3.0-r1_aarch64_cortex-a53.ipk`。

## 2. 安装

### 2.1 安装 nftables 队列依赖（UA3F 透明模式需要）

```sh
# opkg 系（24.10 及更老）
opkg update
opkg install kmod-nft-queue kmod-nft-tproxy

# apk 系（25.12 及更新）
apk update
apk add kmod-nft-queue kmod-nft-tproxy
```

> OpenWrt 25.12+ 若装完进网页报错，执行 `apk add libubox-lua`。
> 如果安装后 LuCI 页面显示异常，清一下浏览器缓存。

### 2.2 安装 UA3F 包

**方式一：LuCI 图形界面（推荐新手）**

1. 打开 LuCI →「系统 → 软件包」。
2. 点「**更新列表**」，等它跑完。
3. 点「**上传软件包**」，选中你下载的 `.ipk` / `.apk`。
4. 上传后点「**安装**」。
5. 装完点「关闭」，然后**退出并重新登录 LuCI**（让菜单刷新出来）。

**方式二：命令行**

```sh
# ipk
opkg install /tmp/ua3f_*_aarch64_cortex-a53.ipk

# apk
apk add --allow-untrusted /tmp/ua3f-*-aarch64_cortex-a53.apk
```

安装成功后，LuCI 顶部菜单里会出现「服务 → UA3F」。

## 3. 路线 A：不依赖 Clash（TPROXY / REDIRECT）

### 3.1 LuCI 里配置

进入「**服务 → UA3F**」：

1. 勾选「**启用**」。
2. 「服务模式」选 **TPROXY**（如果 TPROXY 下不通，换成 **REDIRECT**）。
3. 切到「其他 / L3 重写」页签，勾选「**固定 TTL**」，值先填 `64`（iPhone/Android 人格）
   或 `128`（Windows 人格）——见下方"选人格"。
4. 「重写模式」选 **GLOBAL**（全部统一改）或 **RULE**（按规则，配置文件里已给好规则）。
5. 填「User-Agent」为你的统一 UA（见下方模板）。
6. 按需勾选：`清除 TCP 时间戳(tcpts)`、`IPID 归零(ipid)`。
7. **不要勾**「阻断 QUIC」「Desync」等你没确认需要的项。
8. 点「**保存并应用**」，等待服务重启。

### 3.2 选人格（让所有设备看起来是同一台）

| 人格 | TTL | User-Agent 模板 |
| --- | --- | --- |
| iPhone | `64` | `Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1` |
| Windows | `128` | `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36` |

> 建议选你**认证上网时用的那台设备**的人格。比如你平时用手机开热点认证，就选 iPhone 人格。
> 注意：TTL 和 UA 必须匹配同一个人格，别一个填 128 一个填 iPhone。

### 3.3 命令行方式（等价于上面的图形界面操作，便于脚本化）

```sh
uci set ua3f.enabled.enabled='1'
uci set ua3f.main.server_mode='TPROXY'          # 或 REDIRECT / SOCKS5
uci set ua3f.main.bind='0.0.0.0'
uci set ua3f.main.port='1080'
uci set ua3f.main.rewrite_mode='RULE'           # 或 GLOBAL
uci set ua3f.main.ua='Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1'
uci set ua3f.main.l3_rewrite_ttl='1'
uci set ua3f.main.l3_rewrite_ttl_value='64'
uci set ua3f.main.l3_rewrite_tcpts='1'
uci set ua3f.main.l3_rewrite_ipid='1'
uci set ua3f.main.l3_rewrite_block_quic='0'
uci commit ua3f
/etc/init.d/ua3f enable
/etc/init.d/ua3f restart
```

> 以上键名来自 UA3F 的 OpenWrt init 脚本（`openwrt/files/ua3f.init`）。
> `header_rewrite`、`body_rewrite`、`url_redirect` 这几项在 UCI 里是 **JSON 字符串**，
> 用 LuCI 面板编辑更省事；也可以先在面板里设好，再 `uci export ua3f` 拷走。
> 想用 YAML 全套配置，就用官方模板 `ua3f -g` 生成 `config.yaml` 再 `ua3f -c` 指定，
> 本仓库 `configs/ua3f-config.yaml` 已给一份可直接用的完整配置。

### 3.4 用官方 YAML 配置（可选，最灵活）

```sh
# 在路由器上生成模板
ua3f -g

# 把你改好的 config.yaml 丢到 /etc/ua3f/config.yaml，然后指定启动
ua3f -c /etc/ua3f/config.yaml

# 或者自定义监听端口 / UA 快速启动（默认端口 1080）
ua3f -p 1080 -f "FFF"
```

`configs/ua3f-config.yaml` 里已经填好了 iPhone 人格的 UA，直接抄或在面板里改都行。
注意 YAML 里的 `user-agent` 和 LuCI 里的 `ua` 是同一个东西，改哪边都行，别只改一处又覆盖回去。

## 4. 路线 B：与 Clash / OpenClash / ShellClash 共存

适合：学校有 DPI、你想让一部分流量走加密代理，同时所有 HTTP 流量都经过 UA3F 改 UA。

### 4.1 思路

```
终端 ──► Clash(分流) ──┬──► 加密代理(国外/DPI 流量)
                       └──► UA3F(HTTP 80 等) ──► 直连
```

UA3F 以 **SOCKS5** 模式监听 `127.0.0.1:1080`，Clash 用规则把流量转给它。

### 4.2 UA3F 侧配置

```yaml
server-mode: SOCKS5
bind-address: 127.0.0.1
port: 1080
rewrite-mode: GLOBAL
user-agent: "Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1"
```

### 4.3 Clash 侧配置

最小可用片段（见 `configs/clash-ua3f.yaml`）：

```yaml
proxies:
  - name: "ua3f"
    type: socks5
    server: 127.0.0.1
    port: 1080
    url: http://connectivitycheck.platform.hicloud.com/generate_204
    udp: false

rules:
  - PROCESS-NAME,ua3f,DIRECT     # ① 防止 UA3F 自己的流量回环
  # - DOMAIN-SUFFIX,google.com,Proxy   # ② 需要加密的走代理（可选）
  - NETWORK,udp,DIRECT
  - MATCH,ua3f                   # ③ 其余全部交给 UA3F
```

**关键点：**

- `PROCESS-NAME,ua3f,DIRECT` 必须放在**规则最顶部**，否则 UA3F 会把流量再喂给自己，形成回环。
- 想加密 HTTP 躲 DPI，再加一条：`- DST-PORT,80,Proxy`（把 80 端口 HTTP 流量加密转发）。
- 规则顺序：`PROCESS-NAME,ua3f,DIRECT` → 加密规则 → `MATCH,ua3f`。
- 若 Clash 用 **Fake-IP** 模式，OpenClash 的本地 DNS 劫持要选「**使用防火墙转发**」，
  不要选「Dnsmasq 转发」，否则 UA3F 可能拿不到真实目标。

### 4.4 关于"只加密 80 端口"这条老技巧

早期"无需编译改 UA"的方案就是：Clash 里加 `- DST-PORT,80,proxy`，把 HTTP 明文流量整个加密，
让校园网 DPI 看不到 UA。现在更推荐 **UA3F 主动改 UA + 按需加密**，因为：

- 只加密 80 端口不影响 HTTPS（HTTPS 本来就看不出 UA）。
- 但有些检测也看 TCP 层特征，所以 UA3F 的 L3 重写更全面。
- 真有 DPI 时，两者叠加最稳。

## 5. 应急方案：不动路由器，只在终端上挡

如果你暂时没有 OpenWrt 路由器，可以在支持"重写"的客户端上加规则：

**Quantumult X / Shadowrocket（iOS）**

```ini
^http:// url request-header (\r\n)User-[Aa]gent:.+(\r\n) request-header $1User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1$2
```

**Surge（iOS / macOS）**

```ini
^http:// header-replace User-Agent Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1
```

**Clash 系**：Clash 本身**不支持** URL 重写，只能靠 `DST-PORT,80,proxy` 把 HTTP 流量加密转发。

**局限：** 只能改经过该客户端的设备的 UA，**TTL 仍然会暴露**（除非那台设备是直接拨号上网，
不经过任何路由器）。所以这只是应急，不能替代路由器侧方案。
