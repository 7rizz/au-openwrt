# 04 · UA2F 部署教程（备选方案）

什么时候用 UA2F：

- 路由器性能弱，UA3F 用户态解析扛不住。
- 你只缺"改 UA"这一项，TTL 等用防火墙脚本处理就够。

> 注意：UA2F 靠 netfilter/iptables 抢流，**和 Clash 冲突**，共存较麻烦。
> 如果你的场景需要 Clash，请回 `docs/03-UA3F部署教程.md`。

参考：[Zxilly/UA2F](https://github.com/Zxilly/UA2F)。

---

## 1. 安装（现在有官方 ipk，不用自己编译）

到 [UA2F Releases](https://github.com/Zxilly/UA2F/releases) 下载对应架构的 ipk。
注意文件名里带 OpenWrt 版本，例如：

- `ua2f_4.10.2-r1_aarch64_cortex-a53-24.10.0.ipk` → 24.10.0 用
- `ua2f_4.10.2-1_aarch64_cortex-a53-23.05.5.ipk` → 23.05.5 用

先查架构：

```sh
opkg print-architecture
```

然后：

```sh
opkg update
opkg install /tmp/ua2f_*_aarch64_cortex-a53-24.10.0.ipk
```

> 老版本内核需要 `NETFILTER_NETLINK_GLUE_CT` 标志，官方 ipk 已处理；自己编译才要管。

---

## 2. 配置（UCI 一步到位）

UA2F 的配置在 `/etc/config/ua2f`。最省事的方式是直接用本仓库的脚本：

```sh
sh /root/ua2f-uci.sh "Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1"
```

它等价于：

```sh
uci set ua2f.enabled.enabled=1

# 自动添加防火墙规则
uci set ua2f.firewall.handle_fw=1

# 443 端口流量通常已加密，无需处理
uci set ua2f.firewall.handle_tls=0

# 微信 mmtls 通常加密，无需处理（nftables 分支下该规则无效）
uci set ua2f.firewall.handle_mmtls=0

# 是否处理内网/保留地址，按需
uci set ua2f.firewall.handle_intranet=1

# 运行模式：NFQUEUE(默认) / REDIRECT / TPROXY
uci set ua2f.main.mode='TPROXY'
uci set ua2f.main.listen_port='10010'

# 自定义 UA（注意：UA2F 不改包长度，长度不足会补空格、过长会截断）
uci set ua2f.main.custom_ua='Mozilla/5.0 (iPhone; CPU iPhone OS 17_5 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.5 Mobile/15E148 Safari/604.1'

uci commit ua2f
service ua2f enable
service ua2f restart
```

### 模式怎么选

| 模式 | 适用 | 说明 |
| --- | --- | --- |
| `NFQUEUE` | 默认 | 通过 netfilter queue 改写 TCP 包 |
| `REDIRECT` | 一般场景 | 防火墙把流量 REDIRECT 到本地端口，覆盖本机 + 转发流量 |
| `TPROXY` | 转发流量 | 适合网关接管，但**不处理本机 OUTPUT 流量**（本机流量用 REDIRECT/NFQUEUE） |

### 和其它改 Connmark 的程序共存

如果你还要跑别的会改 Conntrack 标记的东西：

```sh
uci set ua2f.main.disable_connmark=1   # 降低性能，但避免冲突
uci commit ua2f
service ua2f restart
```

### 调优

```sh
uci set ua2f.main.nfqueue_workers='1'   # 1-16，NFQUEUE 模式线程/队列数
uci set ua2f.main.proxy_workers='0'     # 0=自动（最多用 4 个核）
uci set ua2f.main.session_ttl='300'     # HTTP session 空闲过期秒数
uci set ua2f.main.max_http_sessions='0' # 0=不限制
uci commit ua2f
service ua2f restart
```

## 3. 用 UA2F 时别忘了 TTL

UA2F 只改 UA，**不碰 TTL**。所以要配合本仓库的防火墙脚本：

```sh
sh /root/firewall-antidetect.sh install 64
```

（`64` 换成你选的 TTL 人格值。）脚本会处理 TTL、NTP 等；IPID / TCP 时间戳可另行按需加。

---

## 4. 非 OpenWrt 系统

UA2F 自 v4.5.0 起支持非 OpenWrt，但需要自己配防火墙把流量转发到 netfilter queue 的 10010 队列。
编译时要加 `-DUA2F_ENABLE_UCI=OFF`。也可以直接跑透明代理模式：

```sh
sudo ./ua2f --mode REDIRECT --listen-port 10010
```

## 5. 验证

```sh
# 看服务状态和日志
service ua2f status
logread | grep UA2F

# 浏览器打开测试站（不要开 VPN）
# http://ua-check.stagoh.com
```

UA2F 的一个副作用要注意：**它不改包长度**。所以当你设置的 UA 比原始 UA 短时，
末尾会补空格；比原始长时会截断。极少数站点会因此出现异常，遇到怪问题可以换长度接近的 UA。
