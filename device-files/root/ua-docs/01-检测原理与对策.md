# 01 · 检测原理与对策

校园网判定"你在用路由器 / 多设备"的手段，本质上有两大类：

- **被动特征**：直接看数据包里的字段（TTL、IPID、UA、TCP 时间戳……）。
- **行为特征**：靠统计和深度包检测（DPI）推断（时钟偏移、应用流量指纹）。

不同学校开启的项不一样，所以**先判断学校开了哪些，再对症下药**，不要无脑全开。

---

## 六种检测方式对照表

| 检测方式 | 原理 | 现状 | 对策 | 由谁实现 |
| --- | --- | --- | --- | --- |
| **TTL 检测** | 数据包每过一层路由 TTL 减 1。Windows 默认 128，iOS/Linux/Android 默认 64。检测到 127/63 就怀疑你接了路由器 | 仍广泛使用，最有效之一 | 把出站包的 TTL 固定成一个合理值 | UA2F L3 重写 / 防火墙脚本 |
| **User-Agent 检测** | HTTP 请求头里的 UA 泄露系统类型。同一 IP 下同时出现 Windows 和 iPad 特征 → 判定多设备 | **最常用**，也是本方案的主攻目标 | 把所有 HTTP 流量的 UA 统一成同一个 | UA2F / UA2F |
| **TCP 时间戳 / 时钟偏移** | 每台设备协议栈时钟有微小偏移，通过 TCP timestamp 选项做频谱分析区分主机 | 有研究、商用落地存疑，但成本低、偶有学校开 | 清除 TCP Timestamp 选项（或统一为路由器一处发） | UA2F `tcpts` / 脚本 |
| **IPID 检测** | IPv4 头里的 Identification 字段递增区间因主机而异，可据此估计 NAT 后面的主机数 | **基本过时**：iPhone/macOS 长期为 0，现代协议栈不递增，作者认为不现实 | 把 IPID 归零 | UA2F `ipid` / rkp-ipid |
| **Flash Cookie** | 利用 Flash 跨浏览器唯一 ID 标记设备 | **已废弃**：Flash 2020 年就停止支持 | 无需处理（老脚本里的规则已可删） | —— |
| **DPI 深度包检测** | 分析应用层流量指纹（如微信、HTTP 明文特征），或做流重组识别 | 锐捷等设备有，但极耗性能，部分学校不开 | 加密流量 / 分片乱序干扰流重组 | Clash 加密代理 / UA2F Desync |

---

## 哪些可以不管

- **Flash Cookie**：Flash 已经死了，跳过。
- **IPID**：作者原话是"基于 IPID 的检测我认为是不现实且很少见的"。现代设备 IPID 多为 0，
  开着归零也无害，但别指望它是关键。
- **时钟偏移**：如果你已经清了 TCP 时间戳，这一项基本被覆盖。

真正必须处理的是 **TTL** 和 **User-Agent**，这两项是绝大多数学校的组合拳。

---

## 怎么判断自己学校开了哪些

### 方法一：抓包看"裸"流量（最直接）

在路由器上抓内网出口的包，观察：

```sh
# 看 HTTP 请求头里的 UA（在你的手机/电脑上访问任意 http 网站时抓）
tcpdump -i br-lan -A -s0 'tcp port 80' | grep -i user-agent

# 看 TTL 是否为 64/128 的整数（有没有被减过）
tcpdump -i br-lan -vv -c 20 'tcp and port 80'
```

如果你在**不开启任何防检测**的情况下，抓到多条来自不同设备、UA 明显不同（如同时出现
`Windows NT` 和 `iPhone`）的请求，而网络没有立刻断——说明 UA 检测可能没开或阈值很宽松。
相反如果一接路由器就断，基本可以确定 TTL 或 UA 检测在生效。

### 方法二：看断网/封号的触发规律

- 一接路由器就断、且只连**一台**设备时也断 → 很可能是 TTL 检测（因为转发本身就减了 TTL）。
- 单设备正常，**多设备同时上网**一会儿才断 → 典型 UA / 设备数统计检测。
- 只在用某些 App（如微信、部分游戏）时断 → 可能是 DPI。
- 只在高峰期断 → 可能是统计型检测，误杀概率也高。

### 方法三：用测试站验证修改是否生效

- <http://ua-check.stagoh.com> —— UA2F / UA2F 通用，显示它收到的 UA。
- <http://ua.233996.xyz> —— UA2F 教程里用的站点。

> 测试时**不要开 VPN / 代理**，否则 HTTP 被加密，UA 根本没机会被检测，测出来没意义。

## 对策总览（学校开了哪几项就开哪几项）

| 开了的检测 | 你要做的 |
| --- | --- |
| 只有 TTL | UA2F 勾选"固定 TTL"，或跑 `scripts/firewall-antidetect.sh ttl` |
| TTL + UA | UA2F 勾 TTL + 设置统一 UA（最典型组合，直接照 UA2F 教程走） |
| 再加上时钟偏移 | 额外开 `tcpts`（清除 TCP 时间戳） |
| 再加上 IPID | 额外开 `ipid` |
| 有 DPI | 上 Clash 加密代理（`DST-PORT,80,proxy`），必要时开 UA2F Desync |
| 全都开 | 优先用加密代理绕 DPI，UA2F 负责剩下的字段统一 |

---

## 一个重要认知：多一层 NAT / TTL 会"露馅"

只要流量经过你的路由器，TTL 就会比终端直连时少 1（或几层）。
所以**即使你只连了一台设备**，接了路由器也可能被 TTL 检测抓到。
这解释了为什么"只连一台也断"——这也说明固定 TTL 是基础功，不是可选项。
