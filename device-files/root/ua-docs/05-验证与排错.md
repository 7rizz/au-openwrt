# 05 · 验证与排错

改完必须验证。**看不见效果 ≠ 没生效，看见断网 ≠ 一定生效。** 下面按从简到繁的顺序来。

---

## 一、最快的验证：测试站

在**任意一台内网设备**上，用浏览器（**不要开 VPN / 代理**）打开：

- <http://ua-check.stagoh.com>
- <http://ua.233996.xyz>

页面上会显示服务器实际收到的 User-Agent。它应该等于你在 UA2F/UA2F 里设置的那个值。

> 为什么必须关代理：如果 HTTP 流量被加密代理转发，校园网（以及测试站）看到的是加密后的内容，
> 测不出真实效果。做校园网防检测时，UA 修改的意义就在于"明文 HTTP"这一段。

---

## 二、验证 TTL 真的被改了

TTL 是**转发层**的东西，测试站看不出来，得抓包。

### 在路由器上抓内网出口的包

```sh
# 装 tcpdump（如果还没有）
opkg update && opkg install tcpdump

# 抓经路由器转发的 HTTP SYN 包，看 TTL
tcpdump -i br-lan -vv -c 20 'tcp and port 80'

# 或者抓 WAN 侧（NAT 之后）看真实出站 TTL
tcpdump -i eth1 -vv -c 20 'tcp and port 80'
```

关注输出里的 `ttl 64` 或 `ttl 128`：

- 应该**稳定地**是你设置的那个值。
- 如果出现 `ttl 63` / `ttl 127`，说明 TTL 修改**没生效**（被减 1 了）。

### 用 Wireshark 更直观

路由器开了 SSH 后，Wireshark 可以用「SSH remote capture」直接连路由器抓包，现场过滤：

```
tcp.port == 80 and ip.ttl != 64
```

有结果 = 有包没被改成 64，需要排查。

---

## 三、验证 UA 真的被改了（命令行版）

在**客户端**上：

```sh
curl -s http://ua-check.stagoh.com | grep -i -A2 'user-agent'
```

在**路由器**上（测路由器自己的流量，间接验证服务运行）：

```sh
curl -s http://ua-check.stagoh.com | head -30
```

## 四、按症状排错

### 症状 1：装完 UA2F，路由器直接上不了网

**最可能原因：模式选错 / 依赖没装。**

```sh
# 确认依赖
opkg list-installed | grep -E 'kmod-nft-queue|kmod-nft-tproxy'
# 如果没有，装上
opkg update && opkg install kmod-nft-queue kmod-nft-tproxy

# 看服务状态和日志
/etc/init.d/ua2f status
logread | grep -i ua2f | tail -30
```

把模式从 `TPROXY` 换成 `REDIRECT` 再试。仍不通就先关掉 UA2F 恢复上网，再逐项排查。

### 症状 2：测试站显示的还是原始 UA

- 检查「重写模式」是否为 `GLOBAL`（`DIRECT` 是"只转发不改"）。
- 检查规则是不是把目标域名命中成了 `DIRECT`。
- 检查流量有没有真的经过 UA2F：`service ua2f status` + 看统计面板。
- 如果你在测 HTTPS 站点，UA 在 TLS 里，**本来就改不到**（除非开 MitM），要用 `http://` 测试站。

### 症状 3：和 Clash 一起用时死循环 / 自己连自己

- Clash 规则里必须有 `PROCESS-NAME,ua2f,DIRECT`，且**放在最上面**。
- 检查 UA2F 的 `server-mode` 是 `SOCKS5`，Clash 的 `server/port` 与它一致。
- 若两者不在同一网络命名空间，`127.0.0.1` 要改成可互通的地址。

### 症状 4：Fake-IP 模式下部分网站打不开

OpenClash 的本地 DNS 劫持选「**使用防火墙转发**」，不要选「Dnsmasq 转发」。

### 症状 5：微信 / QQ / 游戏异常

UA2F 官方默认配置里已经对微信、B 站、Steam 做了 `DIRECT`（不改）处理——这些客户端对 UA 敏感。
如果你用的是 GLOBAL 模式，可以改用 `configs/ua2f-config.yaml` 里的 RULE 模式。

### 症状 6：开了某些功能后网速骤降 / 网站打不开

**先把"阻断 QUIC""Desync 分片""MitM"全部关掉。** 这些是重武器：

- 阻断 QUIC 会让 YouTube 等回退到 TCP，可能更慢，也可能被识别为异常。
- Desync 分片打乱 TCP，兼容性差，只在确认有 DPI 时开。
- MitM 需要客户端信任 UA2F 的 CA，配置不当会全站证书报错。

### 症状 7：UA2F 改了 UA 但长度变了导致怪问题

UA2F **不改包长度**：UA 短了补空格、长了截断。换一个长度接近原始 UA 的自定义值，
或改用 UA2F（UA2F 会正常改长度）。

## 五、性能与稳定性

- UA2F 是用户态程序，老路由器上留意 CPU 占用：`top -bn1 | head -20`。
- 开 eBPF 卸载（`l3-rewrite.bpf-offload: true`）能提速，但要内核支持，先确认再开。
- 开软件流量卸载（flow offload）时，TTL=255 无法保证（官方文档明确说明），要统一 255 得关卸载。
  一般校园网场景 TTL 用 64/128 即可，不受此影响。

## 六、真的翻车了：回滚

```sh
# 停用并关闭自启（UA2F）
/etc/init.d/ua2f stop
/etc/init.d/ua2f disable

# 停用并关闭自启（UA2F）
service ua2f stop
service ua2f disable

# 撤销防火墙脚本
sh /root/firewall-antidetect.sh uninstall

# 恢复备份的防火墙配置（如果之前导出过）
uci import firewall < /root/firewall.bak && uci commit firewall && /etc/init.d/firewall restart
```
